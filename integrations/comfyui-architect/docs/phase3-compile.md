# 第三阶段：方案到实际工作流（v2.7.0）

第二阶段校验后点击“下一步：绑定图片并编译真实工作流”，或主面板“规划方案→真实工作流”粘贴原始proposal/已校验记录。必须填写原需求，后端重新核整个方案/当前上下文，不相信客户端accepted标记。不再自动扫描改变generation；真实环境已变时须重新生成方案。

只支持当前受控模板，不接受模型返回任意节点JSON/脚本/命令。先读取当前模型和图片可选项，全部明确选择，不默认第一张。换装两图不得相同，确认素材权利/成年人物与实验限制，输入实际画面提示词，再编译。Klein仍4步/CFG1/CPU编码器/单张。2.15.2起面板显示可信任务预览尺寸并允许明确修改，范围仍每边256至1024、16倍数且最多786432像素，不静默改成576×768；实验换装初始尺寸仍576×768。普通任务不预填换装提示词，生成任务需人工填写实际内容，改需求清旧提示词。其他模板使用原具体编译器及校验器，商品布局必须读实际原图尺寸。

结果有真实ui_workflow.nodes/links和API prompt。两个下载明确分开：
- 导出ComfyUI工作流JSON：顶层nodes/links，供画布载入。
- 导出API任务JSON：class_type/inputs，非画布文件。
第二阶段规划记录改名“不是ComfyUI工作流”，不能再拿它当图。插入前确认替换当前画布并先保存，不提交任务。

有限修订：每个面板核验动作最多首次编译加两次显式参数修订，图片/模型/尺寸/提示词四种反馈编号，不读取私密堆栈，不自动调用模型/安装/调种子/运行。重新核验可开启新人工动作，因此不是持久全局配额或自主运行时修复器。第三阶段不声称任意失败图都能修好。

编译前后完整方案/清单复查，关闭/改需求/改方案/改参数清旧图并取消旧回调。接口错误先检查Content-Type，旧后端405明确提示重启，不再JSON解析混淆。UI请求2MiB/4096片/30秒，依赖浏览器合作取消，非全局沙箱。

验收：205 Python单元（新增14），49 mock DOM场景（新增10）。实际8188节点清单生成23节点/27连线JSON，逐UI输入输出slot/连线关系及双参考正负顺序核对。实际样例research/.../phase3-concrete-acceptance/comfyui-workflow.json，API样例独立保存。没有提交/执行推理，浏览器实际载入和重启后HTTP验收仍待用户。之前研究出图不算新接线端到端验收，第四阶段应真实运行并独立检查质量。

# ComfyUI 电商工作流助手项目报告

报告日期：2026-11-16（Asia/Shanghai）  
交付版本：2.15.2  
项目名称：ComfyUI Workflow Architect / AI 工作流架构师  
代码仓库：[wei-boop312/Comfyui-](https://github.com/wei-boop312/Comfyui-)  
报告范围：本 ComfyUI 插件。工作区中后续独立的商业画布应用、用户素材、模型文件和凭证不属于本次交付。

## 1. 项目结论

本项目已形成可安装、可测试的本地优先 ComfyUI 扩展：从中文需求、版本化资料和当前节点能力出发，生成受控方案，经本地校验和人工图片/模型绑定后，输出带实际节点与连线的工作流。已部署并验证本机离线小模型，提供证据摘录和有限模板规划。它已经超出抽象 JSON 方案或资料检索工具，但仍属于电商生产辅助初版。

当前可以交付代码与已验证链路；**整体电商应用尚未全部验收完成**。真实付费 API 仍未接通验收，人物换装仍为实验能力，六张详情页的整体商业画质、复杂视频和多 SKU 稳定生产还未通过。测试通过、节点齐全或 `execution_ready=true` 均不代表成图达到商业标准。

## 2. 用户目标与方案演进

原始方向是 AI 电商无限画布，随后调整为利用 ComfyUI 的节点、模型和执行生态，降低复杂工作流搭建门槛，覆盖主图、详情页、精修、批量图片处理、参考换装与后续视频需求。

智能层采用“本地版本化知识 + 小型离线模型 + 可选线上大模型”的分工：SQLite 保存资料；离线模型选择相关证据与现有模板；线上模型可通过人工 ChatGPT 交换或受控 API 产生规划。确定性编译器负责节点、参数与连线，不让语言模型直接执行脚本、安装节点或任意排队。

开发中的两个实际问题已修正：第二阶段导出的规划记录不能当作 ComfyUI 画布文件；第三阶段现明确区分画布 JSON 与 API 任务 JSON。另一个问题是普通缩放被套用换装提示词并固定成 576×768，2.15.2 已让界面按任务显示并明确提交尺寸，256×256 的实际导出已验证。

提示词库共包含原有 24 张任务卡和新增 56 张七维卡：环境、镜头、产品角度、纹理材质、人物模特、灯光质感、文字排版各 8 张。55 来源/17 配方/10 基础模板构成原 82 份知识记录，加上 80 张卡形成 162 份可检索资料。额外 10 条提示词方法来源独立追溯，不混成执行许可。

## 4. 架构与数据流

```text
中文需求 / 商品事实
       ↓
当前节点能力扫描 + 版本化本地知识 / 提示词库
       ↓
本地规则草案 / ChatGPT 人工交换 / 离线模型 / 可选 API 规划
       ↓
当前上下文、来源、模板、节点签名完整校验
       ↓
人工绑定原图、参考图、蒙版、模型、提示词、尺寸
       ↓
确定性编译器 + 节点参数/类型/连线/依赖校验
       ↓
ComfyUI 画布 JSON / API 任务 JSON
       ↓
显式确认后的本机执行 → 实际 history / 输出 → 人工视觉验收
```

核心代码位于 `workflow_architect/`，前端位于 `web/`，受控模板与资料位于 `workflow_architect/templates/`。入口 `__init__.py` 注册 Comfy 路由与 Web 扩展。`service.py` 协调各层，`registry.py`、`compiler.py`、`validator.py` 处理真实环境与编译，`knowledge.py`、`offline_ai.py`、`api_planner.py` 处理知识与规划，`detail_page.py`、`brand_poster.py` 处理电商输出。

模型返回被视为不可信数据。规划必须绑定当前需求、资料和模板摘要；图片列表变更与真正的节点合同变更分别处理。窗口关闭、需求/参数变化和取消会使旧草稿失效，迟到结果不能更新当前界面。

## 6. 可复核的验收证据

截至 2026-11-02 的最后完整开发记录为 354 项 Python 测试与 115 个前端模拟场景通过。2026-11-16 发布复核的实际结果另见 [发布验证记录](RELEASE_VALIDATION_2026-11-16.md)，包括失败、环境原因与最终命令，不把历史结果冒充今天执行。

历史实际链路包括：

- 本地小模型 → 本地规划校验 → 原编译器 → 独立 CPU Comfy 任务，256×256 输出与自有测试色块逐像素匹配。证明可执行落地，不证明扩散图片质量。
- 2.15.1 日常 UI 对“参考换装为什么不是改色、如何避免重绘手脚”的回答只显示经逐字核对的来源摘录；此前自由回答的无来源扩写已明确修正。
- 2.15.2 日常 UI 使用真实小模型方案，编译并下载 3 节点/2 连线画布 JSON，ImageScale 实际 256×256；规范 JSON SHA 为 `6251c362b0b7e18c97711f9fbacec1e04a7f969584b28a356b745f0ae2cb4ed8`，与页面编译结果一致。导出等待工具中断，但通过实际下载文件核实；没有本轮最终截图，未声称重新导入渲染通过。
- 品牌首屏实际输出 1600×1600；五节点包从独立素材恢复后与原生结果最大色道差 0。日常准备预览与原生结果最大色道差 1。该数值只证明复现，不证明商业质量。
- 自有 HTTP 模拟覆盖“方案返回 → 本地校验 → 图片绑定 → 实际工作流”，没有供应商 API 调用、真实账单或用户密钥。

原始本机证据保留于独立研究归档；本公开仓库只发布去除用户路径和素材的汇总，不上传商品照片、人像、私有工作流、浏览器截图、运行库或原始数据库。

## 7. 离线 AI 与资源要求

当前验证组合是官方 Qwen3-4B Q4_K_M GGUF（约 2.50GB）和固定 llama.cpp b12032 Windows CPU 运行时（下载包约 25MB）。采用 6 线程、8192 上下文、单槽、CPU 推理，不占用生图显存；曾观察模型服务约 5.5GB 内存，属于单机样例而非硬件性能承诺。

端口固定回环 `127.0.0.1:18189`，请求有容量和总时间限制，无云端回退、工具代理或自动重试。SQLite 保存知识；小模型不把知识写进权重，没有自动学习用户文件、后台抓取、Embedding 或微调。

当前部署脚本和部分验收工具仍使用 Windows 的固定示例盘符，跨机器须先审阅并适配。模型、运行时和生图权重不随代码仓库分发；下载与启动均为显式动作。详见 [离线 AI](offline-ai.md)。

## 8. API、凭证、费用与安全边界

API 路径只用于文本规划。Windows 凭证实现使用当前用户 DPAPI 与私有目录，输入通过本人本机隐藏终端，不进入聊天、工作流、提示词或导出。保存凭证不自动联网。历史意向是 Hubway 的 `gpt-5.5` / Responses、单次 0.02 USD；这是配置意向，不是供应商可用性、真实价格或调用成功证明。

费用预检要求独立可信来源，绑定实际目标、模型、请求字节、输入输出上界、倍率、有效期和供应商限额。未知价格/调用结果不补零，不自动重试。当前缺少真实可信费用及限额证据，因此真实执行保持关闭。不得复用历史截图曾泄露的密钥。

本机同源、容量守卫、超时取消和单槽控制不等于操作系统防火墙、生产沙箱、跨进程硬资源闸门或多租户 ACL。关闭窗口不保证撤回已提交任务。已生成合法本地副本不能因事后撤权而宣称被销毁。Comfy/浏览器/素材/画布不存在全局 ACID 保证。

## 9. 安装、测试与交付清单

将仓库放入 `ComfyUI/custom_nodes/ComfyUI-WorkflowArchitect`，先保存现有工作流，再由使用者重启 ComfyUI 并刷新。核心插件没有额外安装依赖声明；图片合成、测试或离线 AI 工具仍需对应宿主库与外部运行时。缺少模型/节点时应保留草稿并显示缺口，不自动下载、换模型或强行执行。

```powershell
python -B tools/run_checks.py --report release-validation.json
```

便携版可将 `python` 换为 Comfy 的 `python_embeded/python.exe`。检查入口显式加入项目路径，避免便携 Python 的隔离导入问题。需 Node.js 运行前端模拟测试；Pillow、aiohttp、cryptography 用于图片、HTTP 与自有 TLS 回归。不在发布时自动安装或升级依赖。

交付内容包括 Python 后端、浏览器前端、基础/实验模板、知识和提示词数据、测试夹具、通用工具、许可证、使用文档和本报告。发布时排除用户素材、模型/二进制、凭证、原始数据库、运行日志、缓存、历史 ZIP 以及只适用于用户私有素材的一次性脚本；具体 SHA 与排除清单写入发布清单。

## 10. 后续建议与完成标准

1. **先完成质量闭环。** 以当前 V3 最低参考图逐项检查产品比例、接触阴影、场景衔接、英文可读性、事实准确和移动端展示；保留原图、工作流和缺陷记录，取得明确视觉验收。完成其余五个模块的独立版式，而非重复一个背景模板。
2. **再做一个真实 API 小闭环。** 先具备有效新凭证、可信价格/限额和明确外发范围，再做一笔受批准请求，记录方案正确性、延时、实际账单与失败行为；在此之前模拟测试不升级为供应商验收。
3. **完善人物与批量生产。** 单独测试参考服装结构、身份、手脚及背景保护；建立有代表性的通过/失败集和人工回退流程，再扩多 SKU、资源调度与恢复机制。视频、换脸仍按独立任务验收。
4. **提高可部署性。** 参数化本机盘符、记录宿主版本、补跨机干净安装及导入回放，建立自动检查与最小示例。新的语义检索应先与现有词法检索比较真实业务收益，避免只增加模型与资源成本。

项目完成应同时满足：能在目标机器安装；真实工作流能执行和恢复；目标任务得到人工质量验收；API/费用/凭证边界经实际核实；发布包可在干净环境复现。当前已完成其中一部分，剩余项按上述顺序推进。

# 知识辅助工作流助手 · 有限初版方案

## 目标与停止线

用户2026-10-15明确授权自主推进，直到项目初步完成或Codex本周剩余<=20%（周已用>=80%）；覆盖历史“用完30%/剩余0%”解释。开始、里程碑结束及约10分钟实际读取周窗口；不可读也停止，不重置/购买或换模型绕过。账号共享取整，检查不能保证零误差。旧项目automation未恢复。

用户最终方向是“本地知识与小型模型 + API大模型协调工作流”，不是重新开发无限画布，也不是只做资料搜索。初版分层如下；没有必要为用完额度重复增加纯草稿层。

## 已落地：2.4.0本地基线

1. 版本化知识：来源、配方和可信模板分级，82记录；外部资料是数据，不是系统指令。SQLite完整记录集和正文摘要校验，不宣称模型权重学习或整库反回滚。
2. 检索：无新增依赖的关键词/中文双字基线；明确不是语义模型。先按任务/运行配置过滤，再核当前节点和模型选项，不把网页配方当执行模板。
3. 人工明确选择：模型和图片默认空选，当前真实选择列表校验；需求/知识/registry变化拒绝旧编译期待。商品布局必须读取实际原图尺寸。
4. 编译与导出：使用原确定性编译器/validator；工作流带知识依据摘要。面板不修改当前画布、不提交/prompt；执行与质量许可分开。

实际ComfyUI已加载2.4.0。真实本机接口完成检索、静态编译、自有图片白名单和旧期待拒绝，队列保持空。浏览器工具拒绝本轮localhost页面操作，没有换浏览器、原生UI或脚本注入绕过；实际面板/下拉与导出下载仍须人工或后续合法工具验收。离线组件测试不能替代它。

## 下一有限阶段：API只规划，不直接执行

授权前默认关闭，不读环境/保险库/钥匙，不创建或推断API凭证，不用“已登录网站”代替API许可。必须明确：供应商兼容协议与endpoint、确切模型ID、币种/单次和总费用上限、调用次数、允许外发的数据与本机凭证配置方式。聊天不接收密钥。

有条件后实现一个可注入规划端口和一个选定供应商适配器，而非同时支持无限平台。先自有假端口测试，再一笔有明确上限的真实请求；无自动重试、换模型或安装节点。普通请求只发送需求、最少节点签名、检索依据与匿名能力状态，不默认发送原图、完整本机路径、完整object_info、执行历史或密钥。

大模型输出严格结构化方案：任务/模板ID/依据ID/必需选择/未知事项；先限定在实际检索结果与本机能力之内。不能输出任意可执行Python、安装命令或绕过预算的图。已有validate_api_choice仅为离线合同，不是实际适配器或许可。UI显示“API方案”与“本地校验结果”，有明确否决与人工确认，不自动/prompt。

## 小型模型：后置可选增强，而非知识仓库本身

SQLite存知识；embedding模型负责索引/检索，不能把“模型文件存在”当已学会节点知识。先保留词法基线，扩充真实业务评测，再比较选定embedding/重排模型是否显著改善召回。下载与依赖安装须另明确确认，优先CPU或按需加载，不未经资源测量长期占用Comfy的8GB显存。不自动读取Comfy里的Qwen权重并把它当检索模型。

每条入库知识保留来源、日期、节点版本、输入输出、模型兼容与许可风险。成功/失败案例先人工审核，防止错误工作流和第三方提示注入自动“学习”。当前没有向量模型、训练、后台抓取或用户历史自动入库。

## 验收清单与不夸大范围

- [x] 知识与模板隔离、损坏拒绝、外来数据库保留。
- [x] 需求/配置/registry变化、模型与图片显式选择、依赖失败可解释。
- [x] 原编译器/验证器与有界导出草稿，无自动执行。
- [x] 自有单元、组件、HTTP和真实Comfy静态接口验证。
- [ ] 实际面板在目标浏览器完成选择、改需求/关闭隔离、下载后再导入校验。
- [ ] 经授权的一个API模型规划→本地拒绝/通过→人工确认的端到端验证。

多阶段自动编排、批量GPU调度、换脸/试穿/视频生成、全新模型模板与商品保真验收不因2.4.0通过而完成。旧解析器不是通用语义理解器；12条手工路由样本通过不代表一般准确率或效果。明确模型专属约束、多任务拆解与风险策略仍须下一阶段扩充，用户应核对最终选择与草稿。纯知识库/JSON/schema/摘要/“execution_ready”都不是质量、许可或付费授权。

# 整合实施计划

当前仅完成第 0 阶段的源码归集。下列各阶段仍待实施和验收。

| 阶段 | 工作 | 验收要求 |
| --- | --- | --- |
| 0 | 固定两项目与 SOP 版本，保留来源及审计问题 | 导入清单、字节哈希和上传目录一致 |
| 1 | 修复审计 D-01 至 D-05 | 越界、环、非法参数、重复提交及测试假阳性都有有效回归验证 |
| 2 | 建立项目、SKU、事实、参考素材、槽位、版本及质量记录 | 一个 SKU 从资料录入至单槽位交付可追溯；其他槽位缺资料不阻塞已满足条件的槽位 |
| 3 | 建立统一任务与 ComfyUI 连接层 | 连接、能力发现、资源映射、提交、状态、结果回收、断线恢复及重复提交防护均通过验收 |
| 4 | 建立套图审核、分槽位导出与交付清单 | 执行成功不绕过商品一致性闸门；未通过图片不能混入合格交付 |
| 5 | 完成跨 SKU、变更影响、案例回流和完整运行验证 | 真正的网页操作、服务依赖、ComfyUI Desktop、故障恢复及真实商品图共同验收 |

## 目标分工

- 电商平台提供已有产品、原图理解与校订、报价快照、任务持久化、事件与供应商调用基础。
- ComfyUI 架构师提供工作流规划、编译、校验、模板与专业编辑基础。其校验缺陷先修复。
- 新增业务层承载 SOP 的项目/SKU/事实/套图/槽位/质量/交付模型。
- 新增连接层将业务任务转换为执行端请求，保存实际执行 ID、输入输出映射与原始回执；状态不明时不得盲目重复付费提交。
- 原有数据库迁移和配置先保留在子工程内，待明确数据模型与迁移方案后再变更。不能仅复制两个 TaskSpec 名称就认为语义已经统一。

## ComfyUI Desktop 验收范围

验证实际安装版本、服务地址与端口发现、访问控制和来源约束、模型及节点能力、输入文件映射、输出取回、多个页面或客户端并发、断线/重启恢复及未知执行状态。

当前没有可交付的 Desktop 连接器，不能把已有网页脚本调用 `/prompt` 当作业务闭环已接通。

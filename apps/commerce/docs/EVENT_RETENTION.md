# SSE任务事件保留

执行包工程契约§8要求默认30天、可配置的事件保留。本工具按用户处理一批，默认只读，不自动调度。它仅清理用于客户端状态追踪的app.task_events；任务、产品、自动/人工报告、供应商回执、积分流水和ops审计事件均不删除。

```sh
python scripts/retain_task_events.py --user <user-uuid>
python scripts/retain_task_events.py --user <user-uuid> --days 30 --limit 1000 --operation-id <uuid> --reason <运维原因> --apply
```

使用私有OPS_ADMIN_DATABASE_URL，要求非owner、非超级、无BYPASSRLS的ops_admin LOGIN。days允许1–3650整数，limit允许1–10000，默认30/1000。有效days每次作为运维配置保存在不可变回执中，没有擅自给用户环境安装定时任务。生产频率尚待用户确定。

严格删除created_at早于当次cutoff的事件；每批有界，不会为了保留“最后一条”而让旧事件无限超过期限。任务最终状态由原业务表保存。过期记录删除、每任务pruned_through水位、不可变操作回执与审计同一PG事务完成，审计失败全部回滚。同用户操作使用事务锁串行；同operation-id与相同参数重放原回执，不会意外再清一批，参数变化拒绝。下一批需要新操作ID。

SSE仍同时支持原生Last-Event-ID和刷新后cursor；服务端先授权，所有水位和事件受租户RLS保护。非零游标小于等于已清理水位时发送stream.reset并重播仍保留的事件，空事件流也能reset；页面已有处理器重新GET任务状态。水位解决“只清掉中间某条、最小/最大仍在时漏判旧游标”的问题。原游标大于最大事件或小于最小事件的保护也保留。不会在等待流时持有PG连接/事务。

新的原生候选覆盖默认期限/实际SSE重置/账务不变、8并发同操作只清一条、稀疏清理与跨用户水位不可见、期限/批量/权限边界，以及审计故障整体回滚。只在GitHub CI创建的合成任务中验证，不对本地用户数据执行清理。完整备份沿用所有表/指纹，但暂不声称已做非空保留回执的专门冷恢复演练。

活动连接记住已读取的清理水位，防止删除最高ID但保留较小近期事件后反复reset；水位增长才重新处理。每次新连接仍重新验证客户端游标，不把旧连接的确认当跨账号授权。初始零游标直接读取当前保留快照，后续循环不会无故重置。

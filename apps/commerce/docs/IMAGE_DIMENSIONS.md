# 图像尺寸与资源边界

新任务每边256–8192像素，正式输出PNG；保护区宽高1–8192，坐标仍需在源/目标画布内且目标区域不重叠。边界直接对照只读原执行包task-create.schema，而非迁就早期小图fixture。

主计划§6.3明确上传单文件20MiB、解码后25MP、每边不超过8192。旧实现实际只有20MP且未显式限制上传长边；本轮统一为25MP/8192，并同步资源受限解码子进程的Pillow阈值，保留内存/CPU限制及像素炸弹检查。原图可小于256，但不符合任务输出下限时不能做同尺寸精确保护；用户需明确上传合适工作图或选择无保护，不静默缩放原图。

精确模式仍要求标准化源图与输出完全同尺寸、总像素≤4MP、至少1个保护区，回贴只平移。无保护输出受统一25MP解码预算约束；因此每边8192不是允许8192×8192绕过总像素限制。API报价/任务验证在冻结前拒绝超限，Fake也在创建本地意图文件和分配图像前拒绝超限尺寸。

平台通用范围不代表每个模型都支持全部尺寸。BFL适配器现有6256单边/4MP协议检查保持不变，未因通用8192范围而放宽供应商协议。未来live报价必须在创建付费意图前同时验证模型能力；当前仍只有offline Fake的默认运行接线，没有真实模型调用。

验证包含原始schema的255/256/8192/8193及保护区8192边界、25MP与4MP不同预算、超限Fake无意图文件、8193长边上传拒绝。真实受资源限制的解码子进程已接受5000×5000 RGB样本（本地测试，不是PG/S3证明）。原生候选另外通过真实API/PG/Worker/S3归档/签名下载校验8192×256、256×8192与5000×5000 PNG、SHA和无保护报告；须等待新提交完整CI实跑后认定通过。

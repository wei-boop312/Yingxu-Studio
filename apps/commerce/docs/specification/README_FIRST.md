# 如何使用这份项目执行包

这份交付已把原计划书改为V4.0工程执行版，包含本机和GitHub资源调查、已发现缺陷、默认技术方案、接口/数据/账务约束及25项开发任务。

1. **先看 [PROJECT_PLAN.md](PROJECT_PLAN.md)**：完整目标、范围、修正项与实施门槛。
2. **让Codex开始开发时，使用 [接手说明](CODEX_EXECUTION/CODEX_START.md)**，并把整个文件夹交给它。接口和数据库细节在 [工程契约](CODEX_EXECUTION/ENGINEERING_CONTRACTS.md)，逐项完成标准在 [任务表](CODEX_EXECUTION/TASKS.md)。
3. **核对可复用资源时，看 [资源调查报告](CODEX_EXECUTION/RESOURCE_AUDIT.md)**。36个本机文件有来源hash，57个GitHub仓库查询有维护/许可线索；原稿已单独备份。

本次实际复跑V2.1测试：156项通过；同时发现其连接池语法错误、旧BFL协议和静态测试边界。工程计划已经整理完，应用开发、真实模型验收及部署尚未执行。

本包优先实现电商图片MVP；同目录历史Word文档中的完整无限画布/Agent愿景保留在路线图。平台官方规则未核清的部分保持人工复核，缺密钥/服务器不阻止先做离线开发。

原位置的 `PROJECT_PLAN.md` 会同步本版，旧稿备份和 `CODEX_EXECUTION` 配套文件放在同目录。压缩包可整体复制到另一台电脑；其中本机资源绝对路径需要在新机器重新定位，并用hash确认来源。

另发现旧Git远程地址内嵌访问令牌，交付包没有包含令牌值；建议轮换该令牌并改用凭据管理器。
